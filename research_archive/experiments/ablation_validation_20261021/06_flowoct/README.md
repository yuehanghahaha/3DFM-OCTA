`2309126956d2b80a95f2d307d85a50799cc658a6`。哈希见 `source/flowoct_snapshot.json`。

## 保证相同的数据

- 直接读取前五组 `data/patches` 下的冻结张量，病例、体块、配准、强度及真值逐元素相同。
- 不再执行原 loader 的 resize、min–max、随机裁剪或翻转，否则比较的输入和评价目标就会改变。
- 只做无损轴转换：`ZYX -> YXZ`；FlowOCT 第一空间轴为 Y/B-scan，推理后再还原 `ZYX`。
- 两阶段的病例/体块顺序直接取自 `01_fm3d/*/schedule.npz`，更新预算同为 400/800，各阶段从头初始化。

## 保留的方法差异

FlowOCT 是二维切片模型，不是三维 U-Net。对 `[Z,Y,X]=[256,64,64]` 输入，模型看到
`[Y,X,Z]=[64,64,256]`，按作者规则抽 `64//4=16` 张 B-scan，每张独立采样均匀时间。
不增加固定 OCT 的第二路拼接条件，不把切片最大投影改成 Z 均值投影。
保留 Adam、beta=0.5、FP32、无梯度裁剪，`network_chunk=0` 整批训练。
因此这是**同数据与同更新数的方法对照**，不是只改变网络维度的一项严格消融；每次更新的体素曝光和计算量不同。

同时导出两个推理协议：

1. `native3`：作者原始 3 步 Euler，每步裁剪到 `[0,1]`。
2. `shared8`：与前五组一致的 8 步 Euler，仅最终裁剪。只改变积分/范围处理，使用同一份训练权重。

评价复用原五组的 `engine.py`：同层坐标、同投影、同固定显示窗、同患者宏平均。
原始 400/800 次更新仍是短程检查，不是论文 200 epochs 的数值复现。

服务器运行入口为实验根目录的 `launch_flowoct_control.sh`。
模型、优化器和原配置签名保存在每阶段 `latest.pt` / `best_validation.pt`；
`final_native3.json` 与 `final_shared8.json` 分别记录两个生成协议。

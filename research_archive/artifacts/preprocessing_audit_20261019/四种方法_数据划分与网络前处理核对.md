# TransPro、XOCT、FlowOCT、CPGMD：数据划分与网络输入前处理核对

> 此版为历史记录。已从本地 Zotero 补读 CPGMD 英文全文并加入 MuTri，请使用[五种方法更新版](五种方法_数据划分与网络前处理核对.md)。下文 CPGMD“全文未取得/划分未确认”的旧结论已由更新版替代。

核对日期：2026-10-19。范围：OCTA-500 的 OCT→OCTA 生成任务；同时区分主生成器、训练辅助网络、验证和测试。本文是论文与公开实现审计，没有训练模型，也没有声称复现论文数值。

**标记：**【异】不同方法采用不同规则；【冲】论文/代码或不同公开入口存在差异；【缺】当前公开证据不足；【示例】只代表作者示例/默认参数，不能当作论文全部实验的确切参数。

## 二、数据表示和主生成网络前的处理

记 Y 为 B-scan 扫描位置、Z 为轴向深度、X 为片内横向。原始 B-scan 自然堆叠为 [Y,Z,X]：3M 为 [304,640,304]，6M 为 [400,640,400]。640 是单张图像的轴向高度。下表保留各方法实际数组轴序，不能把相同的数字排列机械视为相同解剖方向。

| 处理环节 | TransPro | XOCT | FlowOCT | CPGMD |
|---|---|---|---|---|
| 数据文件与配对 | phase/A、phase/B 中独立 NPY；分别排序，按索引配对，检查数量相同，但没有逐例核验文件 ID 一致。 | A/ID.npy、B/ID.npy；按官方 CSV 的同一 ID 配对；同时读取 GT_Layers_npy/ID.npy。 | 每个 NPZ 同时保存 oct、octa；train/validation/test 文件夹决定集合。 | loader 按文件名基名读取 root/FULL/ID.bmp 与 root/OCT/ID.bmp；变量命名与目录语义不一致。【缺】不能断言活动文件就是 B-scan。 |
| 原始 BMP→训练文件 | 作者回复示例逐张读 BMP、按数字切片编号放入体，再存 NPY。3M 注释目标 [304,256,304]，6M 活动目标 [400,256,400]。 | loader 明确要求预先重采样的 NPY：3M [256,304,304]，6M [256,400,400]，Z 在首轴。【缺】完整离线图像/层标签转换脚本未找到。 | 【缺】原始 BMP→NPZ 脚本未发布；loader 注释以 [400,400,640] 为例，即预计 Z 在末轴。不能只凭注释保证所有数据文件方向正确。 | 【缺】原始 OCTA-500 到这两个 BMP 文件夹的导出与病例/切片映射未给出；源码的路径是 OCTAP-600。 |
| 解剖 ROI、去噪、展平、配准 | 可见打包示例先缩放全图；未见明确 ILM–BM 解剖裁剪、展平、去噪或配准步骤。 | 在线 loader 保留预处理体的全部 Z；层标签用于投影监督，不等于裁掉视网膜外体素。【缺】离线有无额外处理不能确认。 | 论文写强度归一化与视网膜区域裁剪；在线 loader 只有 resize 和几何 crop。【冲/缺】论文 ROI 的离线实现未明确。auto_crop 用于损失区域，不是主干输入裁剪。 | CenterCrop 是图像中心几何裁剪，不能称为视网膜 ROI 检测；其他步骤未确认。 |
| 离线重采样 | 作者示例把单张 B-scan 高度缩为 256；3M 横向目标 304，6M 横向目标 400。【冲】粘贴片段把两条 resize 都保留为活动语句，见后文。 | 已知输入体 Z=256、横向保留 304/400；原始 Z=640 到 Z=256 的插值与标签处理细节缺失。 | 默认在线目标为 [400,400,256]；若从原始体开始，轴向 640→256，3M 横向 304→400。 | CenterCrop(400,400) 后 Resize(224,224)；仅能归于公开条件编码器预训练入口。 |
| 在线 resize | 官方 3M 命令 load_size=304、crop_size=256；TorchIO 线性 resize 到 [304,256,304]。即使 NPY 已是该尺寸，变换仍在流程中。6M 专属训练命令未给出；load_size=400 是可选配置而非核实论文配置。 | 官方训练参数 preprocess=crop，无在线 resize。 | TorchIO Resize(load_size,load_size,crop_size)，默认 [400,400,256]；未显式指定图像插值参数。3M 没有单独发布的尺寸命令。 | torchvision Resize，源码未显式设置插值与 antialias 参数；严格复现还应固定 torchvision 版本。 |
| 训练裁剪与取样 | 两个横向轴共享随机裁剪坐标，3M 从 [304,256,304] 得到 [256,256,256]；每次取一个体块。Z 已重采样为 256，不再裁短。 | 保留全部 256 深度；横向共享随机位置取 96×96，得到 [256,96,96]；OCT、OCTA、层 mask 用同一裁剪。 | 先共同随机裁成 256³；再沿第一空间轴随机、不重复抽取 D//4=64 张片，不要求连续；所有病例共用该次切片索引。 | 中心裁剪，不是随机位置裁剪；小于 400 的边会先补零。因此输入是 304² 投影还是 640×304 B-scan，会产生不同裁剪/补零结果。 |
| 强度变换与顺序【异】 | 作者离线片段另有 min–max（位置存在问题）；在线在变换后，对 OCT/OCTA 各自当前裁剪体 min–max，再映射到 [-1,1]。 | 先对整个输入体做 2×(I/255)−1，再裁块；不是逐块 min–max，同一体不同块使用相同尺度。 | resize、crop、flip 后，对 OCT/OCTA 各自裁剪体 min–max 到 [0,1]。 | 8-bit 灰度 BMP 经 ToTensor 通常得到 [0,1]；可见入口没有额外 [-1,1] 或 ImageNet 标准化。 |
| 数据增强【异】 | 官方主生成器命令带 --no_flip，即关闭翻转；保留随机裁剪。论文 VPG 预训练另有随机裁剪/翻转，勿混淆。 | 官方 3M/6M 训练命令均 --no_flip；保留随机横向裁块。 | 训练时概率约 0.5 翻转最后空间轴，两模态同步；按注释轴序，这一轴是 Z，应核对其解剖含义。验证/测试关闭。 | RandomHorizontalFlip(p=0.5)。两张图分别调用随机变换，没有强制同步；但已公开循环仅使用返回的第一张图，不能据此推断未公开生成训练的配对行为。 |
| 增加通道/数据类型 | NPY 增加 C=1；默认批量 1；set_input 转 float32。代码还交换 B/C，只有 B=C=1 的官方示例下无影响。 | 增加 C=1；默认 B=1；图像 float32。标签转三通道 one-hot，再转 float32。 | 增加 C=1；默认 B=1；set_input 转 float32，抽片后把病例与切片维合并到 batch。 | 假设文件本身是灰度图，ToTensor 为 C=1，再复制同一图三次得到 C=3；不是相邻三片。PIL 读取未显式 convert('L')。 |
| 网络前的状态/表示构造【异】 | 直接把归一化 OCT 体送入 3D 生成器。 | 直接把归一化 OCT 块送入 3D MSFF 生成器；包装器另接层 mask 做辅助投影。 | 每片采样 t，构造 x_t=(1−t)OCT+t·OCTA；二维 Haar DWT 得 LL/LH/HL/HH，通道拼接；当前公开 netG 只接状态与 t，没有单独拼接固定 OCT 条件。 | 三通道图送入 AutoencoderKL；采样连续 latent 并乘 0.18215。代码接口预期 4×28×28；2×2 patch 编码为 196 个 token。VAE pretrain 配置/权重缺失，未实测此形状。 |
| 主干最终输入（默认/示例）【异】 | [1,1,256,256,256]，真实三维体。 | [1,1,256,96,96]，真实三维块；辅助 mask 为 [1,3,256,96,96]。 | [64,4,128,128] + 时间 t，二维速度 U-Net；四通道是小波子带。 | VAE 图像输入 [B,3,224,224]；条件编码器/去噪接口预期 [B,4,28,28]；不能把预训练入口等同完整生成训练。 |
| 验证时处理【异】 | train3d.py 的 val 使用同一训练 options，裁剪函数不区分 phase；官方配置下验证仍可能随机裁剪。 | 训练入口的 val 使用中心横向 96×96 块，保留全部 Z；官方关闭翻转。 | 中心裁剪 256³、关闭翻转；全部切片生成后评价。 | 【缺】未找到正式验证数据流程。 |
| 测试输入前处理【异】 | 官方测试默认 load_size=crop_size=256，把输入体整体重采样为 256³；关闭翻转。训练时横向裁块、测试时缩整幅，视野处理不同。 | 官方测试 preprocess=none，读取完整预处理体；3M 4×4、6M 5×5 个横向 96² 窗口，每窗保留全部 Z。 | 仍 resize 到 [400,400,256]，中心 crop 256³；全部 256 张片按最多 32 张一批处理，每一步对当前状态做 DWT。 | 【缺】采样代码和正式测试变换未完整公开；不能声称测试也使用随机翻转。 |
| 测试结果覆盖（便于比较） | 默认生成的是重采样后的 256³，不是原始分辨率全体。 | 重叠窗口计数平均，恢复 [256,304,304] 或 [256,400,400]；不恢复原始 640 深度。 | 重新堆成中心裁剪后的 256³；没有公开全横向滑窗恢复流程。 | 【缺】逐片回拼/全体恢复流程未确认。 |

## 三、辅助网络/监督输入的额外准备

| 方法 | 主干之外还需要什么 | 进入辅助网络前的处理 | 缺失或差异 |
|---|---|---|---|
| TransPro HCG | 预训练二维 OCT→OCTA 投影翻译器 | 对处理后的 OCT 体沿代码 dim=3 求均值，得到 256² 投影；投影单独 min–max 到 [-1,1] 后送 HCG。 | 论文要求 HCG 使用与主任务一致的病例划分；仓库给预训练权重，但缺少完整预训练数据导出与训练入口。统一新划分时需审计权重是否接触测试病例。 |
| TransPro VPG | 预训练二维血管分割 U-Net | 真实/生成 OCTA 的均值投影分别 min–max 到 [-1,1]，再 (P+1)/2 到 [0,1]，以单通道送分割器。 | 论文还使用两位专家补充的毛细血管标注；不是只读原始大血管标签即可完整重建全部前置训练。预训练有随机裁剪、翻转，详细尺寸流程未完整公开。 |
| TransPro 判别器 | 3D 和 2D 配对输入 | OCT 与真实/生成 OCTA 沿通道拼接：3D 两通道体；二维分支拼接相应归一化均值投影。 | 这些拼接是判别器输入，不是主生成器的多模态输入。 |
| XOCT 层监督 | 与图像同网格的三类体素标签 | 0=其他区域，1=ILM–OPL，2=OPL–BM；取同坐标块；构造三通道 one-hot；以 mask 加权沿 Z 求均值，分母加 1e-6，得到 96² 分层投影。 | 原数据的六个层边界面不能直接当作此三维标签体；边界填充、缩放、取整等完整脚本未找到。 |
| XOCT 判别器/感知分支 | 分层投影与条件配对 | 三个区域各自构造 OCT/OCTA 两通道投影供二维判别器；3D 判别器拼接 OCT/OCTA。感知分支把单通道投影扩成三通道送 VGG。 | VGG 均值/标准差归一化在受检函数中只是注释，未实际执行；不能补写为已做 ImageNet 标准化。 |
| FlowOCT 对比/投影支路 | 真实 OCTA 与训练终点估计 | 终点代理先 clamp 到 [0,1]，与真实二维片送对比编码头。另对抽片合并后的 batch 维做 max 得投影监督。 | 该 max 不是全轴均值投影；B>1 时还会混合病例。auto_crop 选损失 ROI，不是对比头/速度主干的输入预处理。 |
| CPGMD 条件预训练 | AutoencoderKL 和 OCT 条件编码器 | 复制灰度图三通道→VAE latent sampling→×0.18215→条件编码器。 | 公开脚本只取 loader 的第一项；FULL/OCT 文件夹的模态含义需确认。不能推断另一个分支的完整 diffusion 加噪/训练过程。 |

来源：[TransPro 输入与投影分支](https://github.com/ustlsh/TransPro/blob/dc748eac63ebffadfe191e96ef85e45e5d3539a0/models/TransPro_model.py)、[XOCT 分层投影包装器](https://github.com/uci-cbcl/XOCT/blob/4bf151bee591880a28556fa18e0a79aee63ade93/models/hybrid_generator.py)、[XOCT 感知分支](https://github.com/uci-cbcl/XOCT/blob/4bf151bee591880a28556fa18e0a79aee63ade93/models/networks_2g_st.py)、[FlowOCT 模型](https://github.com/cnu-medilab/FlowOCT/blob/2309126956d2b80a95f2d307d85a50799cc658a6/models/FlowOCT_model.py)。

## 四、需要特别标记的不一致与缺口

| 标记 | 事实 | 对复现的实际影响 |
|---|---|---|
| 【异】划分 | XOCT 的 3M=140/20/40、6M=200/30/70；TransPro/FlowOCT 的 3M=140/10/50、6M=180/20/100。 | 原论文分数不能直接并列当作同一测试集的结果；统一协议需重新训练和评价。 |
| 【异】强度 | TransPro/FlowOCT 为裁剪后独立 min–max；XOCT 为固定除 255 后映射；CPGMD 可见入口是 ToTensor。 | 即使都显示为灰度图，训练目标与误差尺度也不同，输出需要明确逆变换与评价口径。 |
| 【异】视野 | TransPro 训练横向裁块、测试整幅缩小；XOCT 全横向滑窗；FlowOCT 默认只输出中心裁剪区域。 | “256 深度”“三维输出”都不足以证明评价范围相同。 |
| 【冲】FlowOCT 维度 | 论文描述 3D DWT；公开代码使用 DWT_2D 和 spatial_dims=2。 | 可以复现公开实现，但不能称其已完整重现论文的三维计算路径。 |
| 【缺】FlowOCT ROI | 论文写 retinal cropping；公开在线几何 crop 与损失 auto_crop 不能补全该离线过程。 | 不应把自己的 GT_Layers 裁剪默认为作者原方案。 |
| 【冲】TransPro 打包片段 | 两条分别注释 3M/6M 的 resize 均为活动代码；按原样执行 6M 会先缩宽至304再放大到400；整个体的 min–max 与保存处于逐片填充循环内。 | 应区分“作者片段确实这样写”与“论文实际实验确实这样做”；不能未经确认把该片段原样当标准。 |
| 【冲】XOCT 测试标签 | 论文表示层标签仅用于训练监督；当前公共测试 wrapper/loader 仍读取并传入层 mask。纯 3D 子网络 generator_3d(x) 在 mask 分支之前生成体，不依赖 mask。 | 直接跑脚本需要标签文件；只做 OCT→OCTA 体生成可以单独调用 3D 分支。二者不矛盾，但复现说明必须区分。 |
| 【缺】CPGMD 完整性 | 代码未给出完整生成训练、采样、OCTA-500 划分与原始数据导出；缺少所引用 VAE pretrain。 | 暂时无法仅靠公开仓库实现严格端到端复现；可确认的预训练变换不能当作正式论文全部数据处理。 |
| 【缺】其他离线操作 | 未确认处不能用“医学图像通常会这样处理”补齐；文件夹带 denoise 等字样也不能证明具体去噪算法。 | 所有自补的去噪、配准、展平、分层裁剪都应单独记录为自己的协议。 |

## 五、对统一对照实验的建议

可以统一病例清单、原始数据版本、物理轴/网格、解剖覆盖范围和最终评价程序；保留模型必要的接口适配，如 FlowOCT 小波、CPGMD VAE、XOCT 标签支路。不要在未区分“作者复现”和“统一协议重实现”的情况下，把四种输入强行变成同一尺寸/归一化再与论文数值直接比较。

第一步应先选择共同的病例名单，再明确是否评价完整横向视野以及何种轴向分辨率。TransPro 的 HCG/VPG 和 CPGMD 的条件编码器等预训练模块也要遵守同一数据边界，不能只约束最后的生成器。

本报告没有替你决定新划分，也没有修改任何已有训练/数据处理脚本。

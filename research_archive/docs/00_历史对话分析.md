## 2. 保留的正确理解

### 2.1 训练与生成是两套循环

训练中的一个优化步通常随机抽 t，构造状态，调用一次速度网络，计算 loss，反向传播并更新参数。这个过程重复很多个 batch/epoch，每次都会抽新的时间。因此“随机一个 t”不是“所有参数只训练一次”。

生成时参数固定，沿时间轴多次预测速度并更新图像状态。这个状态更新不等于反向传播。项目中训练 `forward()` 有 `loss.backward()` 和 `optimizer_G.step()`；生成 `generate()` 有 Euler 循环和 `no_grad()`。

### 2.2 FlowOCT 的起点是 OCT

当前代码的配对路径是 `x_t=(1-t)*OCT+t*OCTA`，目标是 `OCTA-OCT`。因此不要把你之前学到的“高斯噪声→OCTA、OCT 是额外条件”原封不动套到 FlowOCT。那是另一种可研究的模型。

### 2.3 训练方法与网络结构应分开

Flow Matching 定义怎样训练速度场；U-Net/Transformer 定义怎样计算速度。`DiffusionModelUNet` 这个类名不会让 FlowOCT 自动成为 DDPM。当前实现没有噪声调度表和 DDPM 的反向采样链。

### 2.4 输出三维体不意味着网络利用了三维邻域

当前模型抽若干切片，合并到 batch 维，用 2D 网络独立处理；推理按相同原则重组体。辅助损失可以使切片之间产生联合监督，但卷积本身没有沿第三个空间轴建模。

## 3. 必须修正或限定的历史结论

| 历史说法/倾向 | 更准确的版本 | 对你设计实验的影响 |
|---|---|---|
| GAN→Diffusion→DiT→FM 是单一升级链 | GAN/FM 是训练机制，DiT 是架构；它们不是按同一标准排列的替代链 | 研究问题从数据和失败模式出发，不能凭“更新”判断更好 |
| Diffusion 绕路，FM 走直线 | 线性配对训练路径不保证学到的 ODE 轨迹完全直；Diffusion 也有 ODE 与加速方法 | 速度必须测 NFE、墙钟时间和质量，不用比喻作为实验结论 |
| 2D U-Net 没有 Transformer，所以没有 attention | 本机锁定 MONAI 1.4.0 后，默认 U-Net 内有 11 个 `SpatialAttentionBlock`；没有启用源 OCT 的 cross-attention | 不能把“加 attention”笼统当创新，要写清新增位置/类型/证据 |
| 作者损失权重纯粹慢慢试 | 代码有固定系数；论文说明了量级校准并提供敏感性实验 | 从损失与梯度量级出发，安排有限对数尺度搜索 |
| 显式 OCT condition 是 FlowOCT 没提出的点 | 公开代码缺少额外源输入；但论文 Eq.(6)/(12) 已明确包含源 wavelet 条件 | 这是论文与代码差异，不能直接包装成新颖方法 |
| 3D 小波没做，所以换 3D 小波就是创新 | 当前调用 2D 小波，但论文第 3.2 节描述 3D DWT；库里也有未使用的 3D 类 | 必须将论文、已释放实现、你自己的变体分开 |
| 400 epoch 是论文实验设置 | 400 是代码默认；论文写的是 200 | 运行记录必须记录实际值与理由 |
| 不确定性采样能告诉你患者真实血管 | 多样性和可信不确定性不是同一件事 | 需校准、错误检测、覆盖率和独立测试；一个 GT/患者也有验证局限 |
| 真正 3D 技术可实现，所以在本机直接用大体训练 | 小型 3D 网络可运行；原分辨率、注意力与训练激活的成本非常不同 | 本机从微型体、2.5D 或 patch 起步，实际测显存 |
| CFM 官方代码已可用 | 2026-10-02 检查其 GitHub 仓库，显示为空 | 它可作为论文参照，不能依赖该空仓库做代码迁移 |

## 4. 对你最合适的主线

建议先提出一个能被否定的问题：

> 在相同患者划分、配准、预处理、训练预算与评价协议下，跨切片上下文是否改善 OCT→OCTA 的结构连续性？

这比“我准备做一个 3D Flow Matching”更完整，因为它有对照、有指标，也允许结果是不改善。

第一阶段只做：原代码跑通 → 数据与评价核对 → 公共 2D baseline → 2.5D 邻域 → 小型 3D patch。第二阶段才研究条件融合、拓扑监督或随机条件流，而且每次只引入一个设计变化。

显式源 conditioning 仍然值得做实验，但研究定位要是“实现并评价论文条件设计/不同条件机制”，不能默认这是新提出的想法。能否形成论文，取决于文献排查、机制证据、对照质量和实际结果，不是是否把一个参数改成 3。

## 5. 怎样判断自己真的理解

你应该能不看笔记回答：

- `x_0` 是谁？`x_1` 是谁？为什么源不是总是噪声？
- `t` 的 batch 长度为什么可能是 B×N 而不是 B？
- 网络输出为什么是 4 通道，而最终图像只有 1 通道？
- 为什么训练不用先积分到 t=1 再算 MSE？
- `detach().cpu().numpy()` 的边框选择与 loss 的梯度有什么关系？
- 当前代码哪个地方真正组合了多张切片？组合发生在网络输入还是损失里？
- 哪些模块是在论文里提出、但公开代码没有完整实现的？
- 怎样排除 3D 结果更好只是因为参数更多、训练更久或评价分辨率不同？

如果你只能回答“因为作者这样写”，就回到对应课程做一次手动修改与验证。

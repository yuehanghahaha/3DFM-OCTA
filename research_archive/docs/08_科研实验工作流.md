# 从一个想法到可信结果：科研实验工作流

更新：2026-10-03。面向 OCT→OCTA / Flow Matching 初学者。

这份文档给出建议流程与设计模板。文中的新配置字段、目录树和消融开关是下一阶段的设计建议，当前作者训练入口尚未实现这些功能；不能直接当作现成命令运行。当前可以直接使用的工具会单独标明。

## 1. 一次实验到底在回答什么

实验不是“加一个模块，训练，看看分数”，而是在限定的数据和预算下检验一个可以被否定的假设。

例如：

> 观察：生成的 OCTA 相邻 B-scan 之间出现不连续结构。
> 假设：只处理单张切片的速度网络缺少邻域信息，导致这类错误。
> 改动：在像素域 FM 中比较单切片输入与三张邻片输入，其他条件保持一致。
> 证据：预设的患者级重建指标、轴含义确认后的结构评价、固定位置的切片和误差图。
> 否定条件：加入邻域后没有稳定改善；或类似增益能由更宽的单切片网络解释。

这是待检验的解释。数据配准、轴顺序、预处理和拼接也可能造成不连续，所以要先排查这些因素。

“有人做过类似结构吗”和“这个结构在我的问题上是否有效”是两个问题。代码能运行不能证明创新，查到一个空仓库也不能证明方法没人提出过。正式投入前要查论文正文、补充材料与相关工作。

## 2. 规范流程与方便迭代的流程可以共用一套

| 阶段 | 要做什么 | 进入下一阶段的依据 | 保留什么 |
|---|---|---|---|
| 定义问题 | 写清观察、解释、改动、主指标、反例 | 可以用一个对照检验 | 假设卡 |
| 固定协议 | 患者分组、配准、轴、归一化、评价 | 数据和指标没有明显歧义 | manifest、协议版本 |
| 建立基线 | 跑通原代码或明确修正版 | 训练、加载、生成、评测闭环 | 基线配置和预测 |
| 实现最小改动 | 只加入必要变量 | 形状、梯度、损失和加载正常 | 代码版本、差异 |
| 小规模验证 | 少量患者学习、固定开发集比较 | 有可解释的学习和收益迹象 | 曲线、耗时、失败例 |
| 完整实验 | 足够训练、多个种子、消融和效率对照 | 主要结论有重复证据 | 每患者指标、完整运行记录 |
| 冻结并测试 | 固定模型、权重选择、推理和指标协议 | 测试结果与预设分析匹配 | 最终表格、限制和复现说明 |

NeurIPS 的官方检查表关注复现途径、数据划分与超参数、统计不确定性和计算资源等。这可以作为检查自己实验是否讲清楚的参考；它不是要求所有研究都使用同一套软件框架。[官方检查表](https://neurips.cc/public/guides/PaperChecklist)

## 3. train、validation、test 各自负责什么

- train：更新参数、学习映射；训练增强只能作用在此集合。
- validation：选择 checkpoint、调学习率与损失权重、筛选想法、选择推理步数。
- test：在上述规则冻结后检验最终泛化，避免反复据此修改模型。

已有官方患者划分时，优先沿用并记录版本；未发布具体患者列表时，需要明确自建划分，不能将不同划分的数值直接视为严格论文复现。

OCT 数据应先按患者分组，再生成切片和 patch。同一患者的双眼、随访、多次扫描应依据患者身份一起分组。一个患者的 256 张切片仍然是一个患者，不是 256 个独立样本。3M/6M 先分开，跨 FOV 评价要明确研究问题。

早期开发集可以是训练集中的少量患者和验证集中的固定小子集。为所有候选保留相同名单，尽量覆盖不同质量与结构。开发集上的长期调参也会造成适应，最终仍需独立测试。

## 4. 为什么公开代码看起来没有评测

可能存在几种情况：指标嵌在验证循环里；只发布核心训练代码；论文表格由未公开的离线脚本生成；代码与论文采用的版本不同。不能仅凭缺一个 evaluate.py 判断具体原因。

当前 FlowOCT 已有：

- `working/util/train_utils.py`：验证时汇总 MAE、PSNR、SSIM，并根据 PSNR 保存较优权重。
- `working/util/util.py`：这些指标的具体函数。
- `tools/evaluate_results.py`：本项目后来补充的独立评价工具。

作者公开版本没有完整提供论文全部前景、感知与分布评价流程。安装依赖列表中有 LPIPS / clean-fid，也不等于已经有可复现的评测协议。

原版 PSNR/SSIM 使用每个 GT 的最大值减最小值作为 data_range；独立工具明确固定 data_range=1，SSIM 为 3D、win_size=7。两个协议不能无条件混用。这里说明的是代码差异，不是在宣布某一个协议普遍最优。

一个指标的名字远远不够。至少要明确：

| 项目 | 必须回答的问题 |
|---|---|
| 输入 | 在处理后的网格还是原网格上评测？强度范围是什么？预测是否 clamp？ |
| 配对 | 预测和 GT 是否对应同一患者、同一扫描、同一空间位置？ |
| 区域 | 全体、视网膜 ROI、GT 阈值前景还是人工血管标注？ |
| 维度 | SSIM 是 2D 切片平均、投影图，还是 3D 体？ |
| 聚合 | 先每患者计算再平均，还是所有体素/切片直接平均？ |
| 异常 | 空前景、常数图像、NaN、完全一致时的无限 PSNR 如何处理？ |
| 可解释性 | 指标是否能检验自己的结构假设？ |

全体 PSNR/SSIM、MAE 可以作为基础，但不能独自支撑“细血管保真更好”。需要结合预设结构评价与固定病例图。没有独立血管标注时，可以做 GT 阈值前景的探索评价，但不能把该 mask 称为人工真实血管标注。

Dice 是定义在预测/真值二值区域上的指标；生成灰度 OCTA 时，需要先明确阈值或分割算法、标注来源与目的。不能为了凑指标临时加入。

## 5. 让评测可复用：生成一次，评价多次

推荐的数据流是：

```text
固定权重 + OCT -> 生成预测 -> 保存每个扫描的数组及元数据
                                       |
                           同一评价程序读取预测与对应 GT
                                       |
                    每患者结果 + 汇总结果 + 固定病例图
```

训练过程中也可以调用同一指标实现做验证，但最终离线评价应能独立运行。增加 MAE、改画误差图、修正统计汇总时，只要预测与网格未变化，通常不需要重新训练。

不能只保存彩色 PNG：色图、量化和插值会改变数据。保存用于计算的浮点预测，同时保留患者/扫描 ID、预处理版本、权重标识、推理配置、空间轴和必要几何信息。

当前独立工具可直接运行。以下命令只演示对已经生成的教学结果评分，不产生新的训练或论文结论：

```powershell
conda activate flowoct
Set-Location '/workspace/FlowOCT'
python tools/evaluate_results.py --input 'artifacts/smoke_synthetic/results/smoke_synthetic/best_epoch_001_psnr_6.8567_ssim_0.0891' --output 'artifacts/smoke_synthetic/metrics_workflow_demo.csv' --threshold 0.05
```

输入 `.npz` 需要包含 `octa`（预测）和 `octa_gt`（GT）。输出逐文件 CSV 与 JSON 汇总。0.05 是教学用阈值；真实实验应在验证集上确定规则后冻结。工具的前景 mask 是 `GT > threshold`，不是论文前景协议或解剖标注。

一次只输入一个实验、一个权重的结果目录；当前工具递归寻找 `.npz`，给它整个包含多个实验的父目录会混合结果。仅在“一文件一患者”时，逐文件平均才是患者平均；多扫描患者需先分组汇总。空前景会产生 NaN，完美预测会产生无限 PSNR，正式统计需预先定义并报告处理规则。

## 6. 如何便捷做消融

消融是构建有解释力的对照，便捷来自统一配置和自动运行，而不是到处注释代码。

例如以同一份修正后的 FlowOCT 基线开始：

| ID | 对比内容 | 需要新训练吗 | 主要解释 |
|---|---|---|---|
| B0 | 完整基线 | 是 | 参照 |
| B1 | 去掉对比学习损失 | 是 | 该训练监督是否有效 |
| B2 | 去掉投影损失 | 是 | 该训练监督是否有效 |
| B3 | 两项都去掉 | 是 | 两项是否有交互 |
| I1 | 同一权重，Euler 1/3/5 步 | 通常不需要 | 质量与推理成本的关系 |

改变训练目标/结构通常要重训。把已经由完整损失训练过的模型在推理时“关掉损失”，无法证明它不需要该损失，因为推理本来就不计算训练损失。

仅改变积分步数、某些后处理或 patch 融合方式，可以先复用同一权重做验证集实验；如果进一步改变训练过程，则属于新的实验。

三个关键细节：

1. 损失权重设为零时，应真正跳过相应计算，记录被禁用项。`0 * NaN` 仍是 NaN。关闭对比损失也不必继续训练无关的 projection head。
2. 去掉小波不只意味着绕过一个函数：网络输入/输出由四个频带改成图像域通道，相应逆变换、网络容量和表示也变化，需要清楚命名。
3. 修复索引错误属于工程修复。结构创新实验都应共享该修复，不能只给新模型修复，拿有 bug 的版本作主要对照。

对 k 个组件，“完整模型 + 逐个去掉”需要 k+1 组，可以用于初步筛选；两个组件的完整开/关组合为 4 组，更有助于观察交互。逐项消融也可能因模块冗余掩盖作用，结论需对应具体上下文。

下面是设计示意，当前作者代码还不能直接读这些字段：

```yaml
experiment_id: pilot_without_contrast_seed17
seed: 17
data:
  manifest_version: octa3m_v1
training:
  max_updates: 2000
loss:
  velocity_weight: 10.0
  reconstruction_weight: 0.5
  contrast_enabled: false
  contrast_weight: 0.0
  projection_enabled: true
  projection_weight: 0.1
inference:
  solver: euler
  steps: 3
```

2000 步只是展示配置含义，不是建议的正式训练预算。关闭开关要由代码明确执行；启动时保存最终配置、检查矛盾项并拒绝覆盖已有运行目录。

## 7. 验证灵感时，分层增加投入

| 层次 | 数据与运行范围 | 看什么 | 能说明什么 |
|---|---|---|---|
| 第 1 层 | 一批真实或人工数据，一次训练更新及生成 | 形状、设备、有限值、关键梯度、保存加载 | 代码闭环可运行 |
| 第 2 层 | 1–2 个训练患者，固定 patch，减少随机增强 | 能否降低误差、生成能否接近训练样本 | 有能力拟合这些样本 |
| 第 3 层 | 固定小训练子集 + 独立验证子集，A/B 同预算 | 主指标、病例图、学习曲线、成本 | 有初步泛化信号 |
| 第 4 层 | 充分训练、独立测试、必要重复与消融 | 稳定增益、效应大小、不确定性、失效范围 | 支撑限定范围内的研究结论 |

这些层次不是统计定理，也不是每个任务必须用相同患者数量。小集学习失败时，优先排查实现和训练条件；小集拟合成功后，还需要独立验证。

对于 FM，训练速度损失下降之外，还要使用只输入 OCT 的生成路径做检查。把含 GT 的 `x_t` 送入网络得到好的单步端点，不等于从 OCT 出发积分也会生成好图。

短训练可以筛选明显失败的方案，但早期领先者可能后期落后。至少为有潜力的候选保留中后期检查，不能把少数步数的排名直接当作收敛后的排名。

尽量保持真实血管尺度的局部 patch。把完整体缩到 32³适合验证运行，但可能抹掉细血管，使实验不再检验原问题。patch 尺寸需要匹配模型下采样、物理轴和显存实测。

共享预训练起点做同预算微调，可以成为廉价探索，但比较对象也需同样微调，且结论只能针对该微调设置。它不能替代从头训练的损失消融。新损失的作用还可能被起点已经学到的特征掩盖。

## 8. 提高速度时，优先减少无效计算

- 固定开发患者清单，避免每次重新随机抽取导致不可比较。
- 可缓存确定性的数据转换；随机训练增强留到取样阶段，不把某一次随机增强误当成永久原数据。
- 先记录数据读取、训练和验证各自耗时，再优化最慢环节。
- 验证可以使用固定小子集筛查；最终评测回到完整预设集合。
- 可重用已保存预测做新的指标和可视化；生成协议变化时重新推理。
- 使用小范围候选，先比较机制，之后才调性能；不要同时扫学习率、所有损失权重、宽度和 solver。
- 失败运行标记为失败并记录原因，自动队列不能把缺失结果记成零分或当作成功。

你的 GPU 为约 6GB 显存，优先顺序执行实验队列。多进程同时训练可能显存不足，也会改变墙钟时间比较。梯度累积、小通道、小 patch 等需根据实测选择；原自定义小波的混合精度路径需要验证，不能假定打开 AMP 就兼容。

## 9. 建设代码时，先形成清楚的职责

下面是建议的下一阶段结构，不代表目录已经创建：

```text
research/
  configs/              数据、模型、损失、预算、推理配置
  datasets/             加载、配对、同步增强、几何信息
  models/               速度网络与条件输入
  losses/               单项损失，返回可求导张量
  solvers/              Euler 等生成过程
  train.py              训练与验证、优化器更新
  infer.py              加载权重、生成与保存预测
  evaluate.py           统一评价实现与逐患者输出
  run_experiments.py    按配置顺序启动和检查运行
  utils/                随机种子、日志、checkpoint
```

一个理想训练步骤可理解为：

```text
读取 OCT/GT -> 采样 t -> 构造 x_t 和目标速度
-> 速度网络 -> 各损失 -> 总损失 -> backward -> optimizer.step
```

推理则是：

```text
加载固定权重 -> x=OCT -> 多次预测速度并积分 -> 保存生成结果
```

建议速度网络的 forward 只返回预测；损失函数只返回损失；优化器更新放在训练循环中。当前作者的 `FlowOCT.forward()` 内部包含反向传播和 optimizer.step，改造成实验代码时需先厘清这一点，不能按普通 forward 的直觉在其他地方额外更新一次。

第一版可以只用几个普通函数，不必马上写插件工厂、复杂继承、分布式训练或数据库。先让一个新损失能在一个地方加入，让所有模型能共用生成/评价接口。

真正 3D 需要一起处理五维状态、时间广播、数据 patch、网络、损失轴与投影、solver 和体重组；不只修改 `Conv2d` 或 `spatial_dims`。可以从已有 `learning/03_minimal_3d_fm.py` 理解最小闭环，但它是人工数据教学代码，没有科研有效性结论。

## 10. 怎样有效地让 AI 帮忙写代码

把修改任务约束到可核查的范围，提供这些信息：

1. 要检验的假设与唯一改动。
2. 输入/输出的含义与形状，例如 `(B,1,D,H,W)`、`t=(B,)`。
3. 要修改的文件、可保留的接口、已有数据格式。
4. 成功标准：关闭新项时可恢复基线路径；打开后梯度和生成正常；同一配置可复跑。
5. 评价协议与工程限制，例如单卡 6GB、患者独立划分、推理不使用目标。

可以请 AI 先画数据流、解释代码差异、实现一个组件，再检查一批数据。让它一次同时重写模型、预处理、训练和评价，会使错误来源更难定位。

代码生成只是加速实现。研究者仍需核查损失公式、轴含义、数据泄漏、训练/推理条件差异，以及文献是否已经提出相同方法。

## 11. 每次运行保留什么，才能一个月后仍看得懂

建议每个运行独立目录，使用明确 ID，例如 `20261003_context3_seed17`。仅文件名里写“最终版”不能恢复实验。

| 内容 | 作用 |
|---|---|
| config.json/yaml | 保存实际生效的所有参数 |
| code_version.txt + diff.patch | 保存 commit 与未提交修改；工作副本不在 Git 下时也需记录差异 |
| environment.txt | Python、框架、依赖、GPU 与驱动信息 |
| data_manifest.csv + hash | 确认数据版本与划分 |
| train_log.csv | 各项 loss、验证指标、学习率、更新步数 |
| checkpoints/ | 模型、优化器、调度器、AMP scaler（若使用）、随机状态与采样恢复所需状态 |
| predictions/ | 预测数组、扫描 ID、权重和推理配置 |
| metrics_per_patient.csv | 做同患者配对比较与失败分析 |
| summary.json | 聚合规则、样本数、指标与异常计数 |
| figures/ + notes.md | 固定展示病例、假设、结论、失败和后续决策 |

checkpoint 仅保存模型权重可以做推理，但不等于精确断点续训。精确恢复还需匹配采样与增强状态，不能只存 optimizer 就声称 bitwise 一致。

固定 Python、NumPy、PyTorch 与数据加载随机性有助于比较；随机增强库也需要检查。固定 seed 不保证跨框架版本、CPU/GPU 或平台得到完全相同结果，确定性运算还可能降低速度。[PyTorch 可复现性说明](https://docs.pytorch.org/docs/stable/notes/randomness.html)

## 12. 哪些软件值得用

| 需求 | 起步实现 | 实验增多后的可选工具 |
|---|---|---|
| 保留代码来源 | Git、commit、差异文件 | 分支与审阅流程 |
| 管理依赖 | 独立 Conda 环境、明确版本 | 进一步环境锁定或容器 |
| 控制实验变量 | JSON/YAML + argparse | Hydra 配置与参数组合 |
| 记录与比较 | CSV、JSON、固定图表 | MLflow 的本地运行管理 |
| 批量训练 | 顺序运行脚本 | 与算力匹配的调度器 |

Hydra 支持通过 multirun 执行多个配置组合；代码需要先接入其配置入口，不能把示例语法直接附在原作者命令后面。[Hydra multirun 文档](https://hydra.cc/docs/tutorials/basic/running_your_app/multi-run/)

MLflow 可以记录运行参数、指标和产物，便于比较实验；它能管理记录，但不会自动保证公平划分或正确指标。[MLflow Tracking 文档](https://mlflow.org/docs/latest/ml/tracking/)

当前阶段无需把这些工具全部装上。明确配置、统一评价、独立输出和可重复运行比选软件更有用。

## 13. 如何判断提升可信

先确定主指标与权重选择规则，再看结果。结构假设可以定义结构主指标，也要保留重建与效率指标；不要见到哪个指标涨就改成主指标。

可以用相同种子列表进行重复，并尽量控制共享的数据顺序与增强。不同网络消费的随机数不同，所以同一个 seed 不意味着所有初始化和随机过程完全一致。

正式比较需要区分两种不确定性：

- 多次训练的 seed 间波动，反映初始化和随机训练过程。
- 同一评测集患者之间的差异，反映病例变化；可以分析同患者两个方法的差值。

多个 seed 的标准差，不能替代患者层面的置信区间，患者层面的误差条也不能替代训练重复。比如对固定的一对训练运行按患者 bootstrap 估计差值区间，得到的是以这对权重为条件的患者不确定性；如果同时包含多 seed，要说明汇总与层次抽样方案。

初步可考虑三个 seed 观察是否稳定，但三个不是通用的充分证明或会议统一要求。应根据效应大小、波动与算力决定重复次数。声明误差条是标准差、标准误还是置信区间，以及其计算单位。[NeurIPS 统计报告要求](https://neurips.cc/public/guides/PaperChecklist)

不要把同一患者切片当作独立患者做显著性分析。多扫描、多眼的采样需维持患者分组。

公平比较至少要共用患者划分、评价协议、输入尺度和选择规则；同时披露训练预算与调参预算。相同 epochs 不等于相同更新数，更不等于相同算力。不同方法可能需要不同合理超参数，应给出可比较的调参机会；机制消融则尽量保持其他条件固定。

失效病例与成本也应保留：哪类结构没有改善、哪类输入产生伪影、显存是否增加、推理是否变慢。只有少数精选图片不足以代表整个测试集合。

## 14. 你当前项目的建议执行次序

1. 把已有原始数据放入 `data/OCTA500/raw`，明确格式、患者 ID、FOV 和三轴含义。
2. 先准备一个 FOV 的成对数据，按患者分组生成 `prepared/train`、`validation`、`test`，用已有数据工具检查。
3. 在少量真实患者上确认修正后的 FlowOCT 训练、生成和统一评价正常；人工数据成功只证明工程闭环。
4. 建立并记录完整的基线配置、预算与验证结果，再实现可配置的损失开关、种子和批量运行入口。
5. 第一轮只研究一个问题，例如“对比损失是否带来稳定收益”，先完整基线与无对比两组，在固定验证集比较。
6. 这组流程可重复后，再扩展投影损失消融、少量 seed 与完整预算。
7. 如果研究邻域信息，另开共同的像素域 FM 对照：2D 与 2.5D，再考虑更重的 3D。不要一次同时改变空间维度、小波与条件输入。
8. 最后冻结选定方法和规则，用独立测试集完成主要对照、消融、效率与限制分析。

每一步的产物都应让你能回答：改了什么、为什么改、比较是否公平、结果支持哪条假设、下一步最值得做什么。
